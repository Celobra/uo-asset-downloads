CentrED# Local - Celobra Edition 0.7.4-celobra.1

Edition identity: 0.7.4-celobra.1. Maintained and published by Celobra.

This version extends Celobra Edition 0.7.3 with blank-map creation, prepared
map tabs and audit fixes. Earlier original and Celobra archives remain separate.

This is an unsigned Windows x64 development build. Published checksums
identify the official bytes; branding does not prevent copying or modification.

Start CentrEDSharp-Local.exe. The .NET runtime, editing engine, interface
resources and native libraries are included. Native libraries extract into
a runtime-managed cache at startup. You still supply your own UO client data.
No separate server, login, account or listening port is needed for local work.
The welcome screen explains the workflow. Help > Quick start and help opens
the guide again. Project > Options > General lets you change the font and
size. Existing display preferences remain.

OPEN YOUR MAPS
Choose Add / create map above the editor, or Project > Maps and working copies.
Browse to your UO client-data folder, use Look for maps, select a map, name
its working copy, then choose Create working copy and open tab. Known map dimensions
are detected. Use Open an individual or custom map when needed; dimensions must
match the index and be multiples of eight.
The source map/statics/index are copied and checksummed before editing.
Artwork remains in the selected UO folder and is read by the editor.

Prepare all maps automatically is enabled initially. Finding compatible
maps creates separate working copies and places
them in the tab strip immediately. Progress, ready and error states show
which tabs can be opened. Preparation runs one map at a time in the
background. Finish or cancel an editing operation before changing maps.
Equivalent MUL/UOP terrain for the same facet is included once; x variants
remain separate. Files with unknown dimensions need your confirmation.
Copies take disk space, and prepared maps take memory. Close unused tabs
to release their memory; their saved working copies stay in the library.

CREATE A BLANK MAP
Open Create blank map and select a UO artwork folder. It does not need to
contain map files, but must contain compatible tiledata and radar colours.
Give the map a name, select map0 through map5, and choose a standard size
or enter custom width/height. Dimensions are measured in tiles, must be
multiples of eight, and must be between 8 and 32760.
Choose the initial land tile and elevation (-128 to 127), then MUL or UOP.
The estimate shows the terrain/index storage required before starting.
Create blank map and open tab writes a new managed working copy with flat terrain and empty
statics. Progress and Cancel remain available during generation. Creation
checks the generated data before adding a ready editing tab. It does not
overwrite a map in your selected artwork folder.
New UOP maps use uncompressed legacy MUL chunks in the map's own facet
namespace. Use matching artwork and test exports with your receiving client.

MAP TABS
Tab names follow the source map, including map0x and other variants when
they have matching statics/index files. Ready maps stay prepared so clicking
another tab does not repeat its full map scan. The active working copy is
saved at the transition; a failed save keeps that tab selected.
Each map keeps separate project files, checkpoints, camera, display settings,
navigation and Undo/Redo history while its tab remains open. Undo never
crosses maps. Camera/display state survives restarting the application;
Undo/Redo history lasts for the open editing session.
Finish or cancel a large operation or image export before switching tabs.
Closing a tab saves it and retains its project in the library for reopening.

The working map, settings, profiles, logs, blueprints and checkpoints live
in your Windows local application-data folder under CentrEDSharp-Local.
You can choose another location with --data-dir followed by a folder.
Keep adequate space for a working map and its recoverable checkpoints.
Checkpoints contain a complete map/statics/index copy. A large operation
keeps copies before and after it for Undo/Redo. Automatic backups retain
twenty copies; manual checkpoints and operation history copies are retained
on disk until you remove them. Check storage use before large map operations.

NAVIGATION AND EVERYDAY CONTROLS
The action bar provides Save map, Undo, Redo, Checkpoint, Go to, Inspector,
Layers and Help. Go to opens coordinates, bookmarks and the minimap. Type X/Y
then press Go or Enter. Ctrl+L focuses coordinates; Ctrl+Home centres the map.
Back and Forward revisit explicit destinations. Resize the navigation window
to fit the minimap. Save bookmark records the view centre; names can be searched,
renamed or deleted. Each local map keeps separate bookmarks.
Search artwork by part of its name or an exact decimal/0x hexadecimal ID.
Clear search restores results. Choose Terrain or Objects, and List or Grid.
Select a tile to inspect it; Use graphic and Use hue open their pickers.
Right-click the map for tool switching and graphic/height/hue sampling.
Layers controls the visible height range and separate graphic/hue filters.
Show all layers resets height only. Help > Reset layout opens a confirmation.

AREA SELECTION AND VIEW BOUNDARIES
Large scale operations and Layers > XY view boundaries provide Pick area.
Click the first and opposite corners on the map or minimap. The corners are
inclusive and work in either order. Escape or Cancel area keeps the previous
coordinates. Picking fills the fields; it never starts an operation.
XY boundaries hide terrain/statics outside a region without changing the map.
They are separate from height, graphic and hue filters, and are saved in the
map's display presets. Show all XY restores the full map. Hidden tiles cannot
be selected for editing; picture export uses the bounds captured when started.
Image overlays and the virtual plane are hidden while XY boundaries are enabled.

WORKSPACE LAYOUTS
Workspace on the action bar opens the layout manager. Save named arrangements
of panel visibility and docking positions, load them, rename or delete them.
Editing/Inspection choices switch useful panels. Restore previous brings back
the last arrangement. Changes preserve recovery copies before applying.
Maps, map tabs, bookmarks and display presets are separate from workspace files.
Leave area selection and player preview before applying a layout.

PLAYER VIEW AND REAL CLIENT TESTING
Player view > Start at view centre places a male or female character in the
current map. Focus the map and use WASD or arrows to walk; Escape or Return to
editing restores the previous camera and display. Ignore collision lets you
inspect freely. Hide objects above player is an approximate roof inspection.
Movement, ground and clearance checks are estimates. Doors, live server objects,
scripts, equipment and shard movement rules require the real client/server.
Supported character animations must exist in your project's artwork folder.
Preview movement does not edit map tiles. Leave preview before switching tabs.

Open real-client testing lets you browse to your existing client executable,
supply optional arguments and explicitly launch it in its own window. It uses
its own configured data and server. Export test map creates a separate folder
with terrain, statics/index and a checksum/artwork manifest. Install that export
into matching test client/server data before testing. The editor does not copy
files into your client, create an account or connect you to a shard, and changes
do not appear live in an already running client. Client settings remain private
on this computer.

SAVE AND RECOVER
Use Save map (normally Ctrl+S). The status shows unsaved edits and the
last save time. Closing saves and waits for the engine to finish. A failed
save keeps the application open and reports details in Activity.
Use Keep a checkpoint before experimenting. Under Checkpoints and recovery,
Restore selected checkpoint keeps a checkpoint of the current map first
and clears the previous undo history. If automatic recovery has failed,
the working map is held for recovery: edits, saves, exports and automatic
writes are stopped, including after restarting. Restore a verified checkpoint
to clear that condition; a failed restore keeps the map held for recovery.
The restore flow skips making a new checkpoint from an uncertain held map.
Restore last saved map verifies the retained pre-edit recovery copy and
returns to that committed map if the operation checkpoint cannot be used.
Edits after that save are discarded only after you confirm the restore.
The recovery record restores the last committed files after interrupted
editing/saving. Edits after that committed save may be lost in a crash.
The first edit after a save makes a recovery copy; large maps can pause
while this completes. Autosave/checkpoint retention is configured per project.

EDITING TOOLS
Paint, move, height and replacement operations validate coordinates and
heights. A replacement is deleted only when its preview supplies a new tile.
History has names, bounded undo/redo groups and separate project sessions.
Use Tools > Large scale operations for a region or facet, preview the count,
then apply. Progress and cancellation are available. A cancelled local
operation restores its checkpoint. Cancellation of a remote operation can
leave accepted remote edits; its status explains this.
Use Tools > Find, replace and cleanup to inspect duplicates, invalid IDs/hues,
missing artwork
and incomplete tree assemblies, or search/replace filtered statics. Review
the preview before applying. Cleanup suggestions depend on the artwork and
tree definitions supplied by your project.

BLUEPRINTS AND TERRAIN
The blueprint library includes art previews, searchable tags, anchors,
rotation, mirroring, and floor/roof/height filters. Transformed placement is
validated before applying. Exported blueprint metadata retains source IDs,
coordinates, heights and hues. Source metadata hashes identify matching
artwork. CSV building exports include a checksum-verified interchange
manifest. Explicit decimal graphic/hue mappings can be reviewed and enabled
when importing into different artwork; the source building is preserved.
Read BLUEPRINT-INTERCHANGE.md for the mapping format and recovery details.
The editor does not allocate or install artwork IDs automatically.
Land brushes use deterministic side/corner matching and report missing or
ambiguous transition definitions. Complete definitions produce better edges.

DISPLAY AND IMAGES
Project > Options > General provides display presets and artwork reload.
The Keymap tab provides shortcut remapping and conflict hints; Lights
controls lighting. Text size can be adjusted from 10 to 40 in General.
Presets include filters, lights, flat view, camera orientation, grid and
overlay settings. An artwork-change notification offers controlled reload.
Reload runs between operations and preserves accepted map edits/history.
Reloading changed tiledata can require repairing now-invalid placed items.
Image export renders bounded tiles, shows progress/cancel and writes its
final image only after completion. PNG supports larger images than JPEG.
Finish/cancel image export before closing or switching projects.

EXPORT MAP FILES
In Maps and working copies, choose Export a map copy and a parent folder.
A new export
folder contains map/statics/index plus checksums and an artwork identity
manifest. Original graphic IDs are retained. Use matching artwork/tiledata.
Exports are not installed automatically. Back up receiving files and test
your exported copy in your own client/server before using it as a live map.
UOP map support is bounded by the format checks; unsupported compression is
reported rather than silently edited. Use compatible uncompressed working
files when required.

OPTIONAL COLLABORATION
Collaboration is separate from local projects. Joining uses TLS by default
and requires a trusted certificate matching the hostname. Hosting requires
its own XML configuration and certificate and defaults to loopback.
Explicit legacy mode is available for old CentrED/CentrED+ peers; it uses
unprotected TCP. Old server account hashes migrate after successful login.
Saved Windows passwords use your Windows account's protected storage.
