# Map workspace in 0.7.4 Celobra Edition

Choose **Add / create map** above the editor, then **Open UO maps**. **Prepare all maps automatically** is checked by default. Browse to your client-data folder or enter it and choose **Look for maps**. Recognised maps immediately appear as separate pending tabs. The editor copies and validates them in the background; each tab becomes **Ready** after its backend and minimap are prepared. You can continue editing a ready map while the remaining maps load. Hiding the Maps window does not pause completion.

`map0`, `map1`, `map2`, `map3`, `map4` and `map5` have independent tabs. Extended `map0x` and `map1x` files remain separate. Equivalent MUL and UOP terrain files for the same facet produce one tab, favouring the format already open and otherwise MUL. The matching statics and index are required for either format. A custom map whose dimensions cannot be identified is listed as **NeedsDimensions**; choose its file under **Open an individual or custom map**, enter the actual width and height in multiples of 8, name it and create its working copy.

Select a ready tab to switch maps. The current working copy saves before the selection changes. Each tab retains its position, zoom, layers, view bounds, lighting, navigation visits and named Undo/Redo history. Undo/Redo survives switching while the editor remains open; it is not serialized across restarts. Saved view and navigation settings are restored on reopening. The same-folder artwork remains shared; every ready map retains its own backend, so switching avoids rebuilding its minimap. Ctrl+Tab and Ctrl+Shift+Tab select the next and previous ready map when a text field is not capturing the keyboard.

Pending tabs show copying or validation stages. **Cancel all preparation** remains at the top of the Maps window; individual jobs also have **Cancel**. Cancellation removes incomplete creation output. A copy already committed before cancellation remains available under **Saved maps**. A failed map displays its own error and a **Retry** action; other ready maps stay available. A recovery error in the active map requires restoring its verified checkpoint before saving or switching. If the operation checkpoint is damaged, **Restore last saved map** can recover the last committed map from its verified pre-edit record; confirm this before discarding the failed unsaved operation. Preview, area selection, bulk edits and image exports also pause switching until they finish.

Under **Create blank map**, choose a matching artwork folder and **Load terrain choices**. Existing maps are optional. Name the map, select its facet and standard, classic, practice or custom dimensions, choose fill terrain and elevation, and select MUL or UOP. Terrain names come from that folder's tiledata; search the picker or use the advanced numeric ID field. The size preview shows the new terrain and statics-index file space. A new map contains flat terrain and no statics; it is streamed into a new managed working-copy folder, validated and opened only after creation succeeds. Terrain does not have a hue setting.

The map library holds up to 32 open/preparing tabs. Ready backends retain three working-file handles, their radar data and bounded caches; only the active map uses client/GPU rendering resources. Inactive prepared maps do not run periodic saves or automatic backups. Close a tab to release its backend and history. Its saved working copy remains available under **Saved maps**. Editor restart asynchronously prepares the saved tab list and selects the last active copy when it is ready.

**Current map / recovery** contains Save map, Keep a checkpoint, Export a map copy, working-copy details and checkpoint restoration. Working copies live in the application's private data folder; preparation and blank generation never replace files in the selected UO artwork folder.
