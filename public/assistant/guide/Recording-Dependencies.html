Recording tools, matching source and rebuilds

UO Assistant 0.3.0 uses separate FFmpeg programs and libraries for optional recording, replay and video export. Normal users receive the checked tools in the installer. The source downloads below are for inspection, modification and rebuilding; recording does not require downloading the large dependency-source packages.

The exact distributed tools

The selected upstream build is N-127579-g5cb9fcd211-20261016, win64-lgpl-shared, from BtbN's immutable autobuild-2026-10-16-13-04 release. The application runs ffmpeg.exe and ffprobe.exe as separate background programs, with their original avcodec-63, avdevice-63, avfilter-12, avformat-63, avutil-61, swresample-7 and swscale-10 DLL identities retained. It does not embed FFmpeg code into the game or assistant assembly.

Separately licensed dependencies retain their own terms and copyrights. See the matching dependency license/copyright collection and complete source trees.

What the source packages contain

The FFmpeg snapshot is commit 5cb9fcd21167cf2f5a2852ea582997bbd0055521. The complete upstream build-recipe and patch snapshot is commit 63ac3265b0789ea16c7b1f8351cd2ad195a28722 of BtbN/FFmpeg-Builds. The kit also contains actual output from the distributed executable's -buildconf and -version, binary tool hashes, source archive hashes, license texts and a source preparation helper. UO Assistant applies no FFmpeg algorithm/source changes; its FFmpeg changes file is empty.

Both dependency parts contain all 129 matching source download-cache archives from the same upstream build workflow. This is a complete source-cache superset: it also retains unused GPL/nonfree/Linux-only source options for completeness. Their presence as source does not mean they are linked into the shipped LGPL Windows build, and does not change the selected build's configuration. Each dependency archive has its own hash in media-source-manifest.json, with original source-level licenses/notices retained.

Preparing and building the media tools

  1. Download the source/rebuild kit and both dependency parts from this same version. Verify their release hashes and keep the three ZIP files together.
  2. Extract the source/rebuild kit. With Python 3.12 or newer, run python3 prepare-rebuild.py ../media-rebuild from its extracted directory. The destination must not already exist. The helper verifies source and dependency hashes, prepares the pinned source tree and recipe cache, and adjusts the copied build helper to use the bundled FFmpeg source and historical version/date metadata. It does not run a build or access a network.
  3. On Linux, with bash, Docker and buildx, enter the prepared FFmpeg-Builds-63ac3265b0789ea16c7b1f8351cd2ad195a28722 directory. Read the included upstream README and scripts before running:
./makeimage.sh win64 lgpl-shared
./build.sh win64 lgpl-shared

The matched dependency-source cache is reused. Building the normal compiler/OS environment can require standard package repositories. Recipes and enabled flags are supplied, but a byte-identical binary is not promised: compiler/OS package versions and timestamps can differ. Verification for this release prepared the complete public source kit and all 129 dependencies successfully; a local Linux/Docker compilation was not performed.

Using compatible modified tools

You may inspect, modify and rebuild the media libraries under their applicable licenses. Their modification and reverse engineering needed to debug those modifications are not prohibited. FFmpeg copyright belongs to its developers and other contributors identified in the sources; FFmpeg is a trademark of Fabrice Bellard. UO Assistant does not claim ownership over those components.

The official launcher pins its program files, and the recorder also checks its local media-tools.json. Replacing a DLL in the official installation without regenerating those integrity records will fail the checks. Use a separate rebuilt application directory and the matching complete UO Assistant source and launcher source. No private release-signing key or online authorization is required for that rebuild.

  1. Keep the official installation unchanged. In a fresh development copy, preserve the client/companion's complete manifest-listed program files and use compatible FFmpeg executable/DLL names and APIs.
  2. Replace the media tools in that copy's Client/Companion/MediaTools. Regenerate its local media-tools.json dictionary from the SHA-256 of each of the nine named executable/DLL files.
  3. Regenerate the copy's Client/runtime-manifest.json with the complete relative-path, length and SHA-256 list, including the changed tools and media manifest. Do not include personal profiles, game assets, accounts or logs.
  4. Publish the supplied Launcher/Build-Launcher.ps1 against that copied Client directory using fresh build/output directories. The script embeds the newly generated client-manifest hash in your rebuilt launcher. Copy its complete self-contained output beside your copied Client folder, then use its verification mode before starting a game.

The official release payload builder intentionally requires the official media hashes. For modified media, rebuild the local manifests and launcher as described instead of changing the preserved official installation. Keep any redistributed modifications' source, applicable notices and required recombination material available under the components' licenses.

Recording is optional. Hardware support, chosen codec, quality, resolution, scene content and frame rate determine file size and encoding cost. A source-package or integrity check is not a live gameplay performance test. The application does not promise a universal smallest file or identical quality on every GPU.
