GPU recording and replay

UO Assistant 0.3.0 preview records its paired game window using hardware video encoding. The assistant stays in its own window. Clips remain local; this feature does not upload them. Recording and replay are off until you start them, and the microphone is always off.

Make your first clip

  1. Start the game through the launcher and enter the world. Keep the game window restored. Open Recording in the separate assistant.
  2. Start with Auto, Balanced, 60 frames per second and the default 1920-pixel maximum width. A smaller game window keeps its own resolution. Use width 0 to keep native width.
  3. Choose whether to include game-only audio and the game cursor. Leave the clips folder blank to use your Windows Videos folder's UO Assistant subfolder, or choose a local folder. Save the recording settings.
  4. Choose Start recording. The status shows the selected encoder, encoded frames per second, encoded size, encoder CPU and reported dropped frames. Then play normally.
  5. Choose Stop and save. Wait for finalization, then choose Open clips folder. The application verifies the resulting MP4 before removing the completed recovery segments used for it.

Video capture requires Windows 10 version 2004 or later and a compatible graphics driver. Game-only audio requires Windows 11 or a supported Windows Server version. On an older Windows version, turn game audio off. No system-audio mix or microphone fallback is started.

Choose quality and file size

Auto codecProbes hardware encoders, beginning with HEVC, then AV1 and H.264. It does not silently switch to CPU encoding if hardware support is unavailable.
HEVC, AV1 or H.264Choose explicitly when you need a particular format. H.264 is useful for sharing with common players. Verify your recipient can play the chosen format.
Compact / Balanced / DetailedCompact accepts more visible compression for smaller clips. Balanced is the starting choice. Detailed spends more data on detail. Inspect small text in a short clip before a long session.

Maximum widthChoose 1280, 1920, 2560, 3840 or native width (0). Smaller output saves data but also reduces readable detail. Odd dimensions can be cropped by one pixel to fit an encoder's even dimensions.
Maximum NVENC bitrateThe NVIDIA VBR cap is configurable from 2 to 100 Mb/s. This is a maximum, not a promised file size. Intel and AMD encoder settings use their own supported quality controls.
Game audio / cursorBoth are optional. Game-only audio follows the paired game process tree, not the computer's full audio mix. The microphone has no enabled capture path.

The smallest acceptable file depends on your scene, resolution, frame rate, quality and GPU. Short NVIDIA quality tests produced similar measured text detail with the three codecs, and HEVC produced the smallest files in those runs. This does not establish a universal smallest-file codec.

NVIDIA hardware capture was tested. AMD and Intel choices are available through runtime capability probes and still need testing on the receiving system. GPU capture and encoding run outside the game's render loop. The application uses bounded queues instead of making a game frame wait for video output.

Save recent moments

Choose Start replay buffer instead of ordinary recording. Set a duration from 10 to 300 seconds and an encoded disk budget from 32 to 2048 MiB. This stores compressed segments on disk; it is not a raw-frame memory buffer.

Choose Save replay to make a new MP4 while the buffer continues. A complete segment must exist first. A replay export ends at the last complete segment, so the newest approximately two seconds can be absent. Wait briefly if the moment you want just happened. The disk budget can shorten the retained duration for complex or high-bitrate scenes.

Stop and save stops the active buffer and attempts to save its remaining complete recording. One capture session runs at a time. Stop it before changing the recording settings.

Recording shortcuts

Configure keyboard, mouse side-button or wheel bindings in the input editor. Use the ToggleRecording, ToggleReplay and SaveReplay actions. Recording and replay toggles stop and save an existing capture; when idle they start their corresponding mode. Choose your own shortcuts and context rather than assuming an unconfigured key is active.

Tap fires once; operating-system key repeat does not repeatedly start or stop recording. A Hold binding waits 350 milliseconds and fires once. Context and per-binding pass-through settings also apply. See the native controls guide.

Trim a copy

  1. Choose a recorded MP4 or MKV in Trim an existing clip.
  2. Enter the start time and length in seconds. The range must fit inside the clip.
  3. Choose Save trimmed copy. The original file is preserved. The new MP4 copies compressed video without another quality loss.

These cuts follow nearby keyframes. They can include up to about two seconds of extra footage instead of making a frame-exact re-encoded edit.

Stop, closing and recovery

Minimizing or closing the paired game stops capture and attempts to save complete video. Closing the assistant finalizes its capture and closes its paired game. A changed or replaced game window is not silently substituted with another window or the desktop.

If the encoder, audio pipe, file system or finalization fails, the application preserves the session's complete segment files under the clips folder's .recovery directory. Keep that directory until you have recovered or copied the video you need. The newest unfinished segment may be unusable after an interruption. Recovery files are private and are not part of a release package.

Recording stops at its disk-space or eight-hour safety limit. Finalizing an MP4 needs additional free disk space for the output. A full disk can prevent finalization; complete recovery chunks are retained. Avoid manually renaming, replacing or deleting a session's files while capture or export is using them.

Troubleshooting

  • Enter the game: normal recording requires the assistant's paired game and an active player session. It cannot choose an unrelated window.
  • Restore the game: a minimized or unavailable capture window is refused. Restore it, then start a new capture.
  • No compatible encoder: check the driver or try another supported codec. Automatic CPU video encoding is not enabled.
  • Game-audio error: check the Windows requirement. Turn game audio off to make a video-only test; the application does not switch to desktop audio.
  • Choppy video: inspect the game's own frame timing and the recorder's dropped-frame count separately. Try 30 FPS, a smaller output width or another quality level.
  • Unverified or missing recording tools: repair or reinstall the checked application. Executables and their component files must match the included recording inventory.
  • Saved file will not play: test H.264 or a player that supports the selected codec. Preserve recovery files when the application reports an incomplete export.

What was tested

Automated hardware tests captured an owned synthetic moving-grid/text window through the production GPU recorder, encoded HEVC, AV1 and H.264, included process-scoped audio, decoded frames for text inspection, saved replay and trimmed a copy. Separate network-fenced native client UI runs compared frame timing with the action bar and recording enabled. No player credentials, live world or desktop capture were used.

Those synthetic results do not guarantee live shard performance. Check walking, running, gumps, targeting and a short recording on your own receiving system before relying on a long clip.
