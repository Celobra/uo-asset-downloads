UO Assistant

A GPU game client with a separate assistant window. Version 0.2.1 is a development preview.

Install

Run the setup EXE and follow the installation steps. Installation is for your Windows account. The client, assistant and their .NET runtimes are included; PowerShell and a development SDK are not required.

Your shard's game data is separate. Use a complete client installation supplied for your shard, including its custom maps and artwork.

Connect to a shard

  1. Open UO Assistant from the Start menu or desktop shortcut.
  2. Add a profile and choose the shard's client folder or client.exe. The launcher reads the version and available game data without running that executable.
  3. Check the server address and port. Use the shard's own instructions for the encryption setting. The launcher can read one active address from Login.cfg; you can enter a different address explicitly.
  4. Save the profile, then choose Play. The game and separate assistant open together. Log in manually in the game.

You can keep different profiles for different shards. Each profile keeps its own character settings, history and assistant rules.

Play and use the assistant

The game handles movement, gumps, object clicks and targeting. Its compact display shows completed Draw FPS, process CPU and frame timing. Start with the default 60 FPS and VSync settings.

Use the assistant's dashboard, journal, inventory, aliases, macros, scripts, counters, agents and other tools. Nothing runs at login. Configure a rule and review its preview before choosing Run; watches require a separate explicit start.

Closing either the assistant or the game closes its paired application normally. Stop all cancels further queued automation. Actions already sent to the shard cannot be recalled.

Potion, bandage and custom countdowns

Open Cooldowns in the separate assistant. Choose Add example presets for editable healing potion, cure potion and bandage rows. Existing profiles keep their current definitions. Select a row, set Duration (seconds) to your shard's timing, then save it. Fractional seconds are supported. Add other named timers for abilities, food, buffs or any reminder you need.

Choose Manual to start/reset a countdown yourself, Item use to observe an owned item's use request, or Journal message to start from a literal message your shard sends. Automatic tracking is off for the starter rows until you enable it. Match an item's graphic and optionally its hue (a blank graphic matches any owned item use); a loaded-inventory selection can supply those values. Journal matching uses literal text, not a programming expression. An optional ready message ends the countdown early.

A potion-use countdown estimates when the action may be ready; a request can still be refused by the shard. A bandage countdown estimates the completion time after the configured start message. These timers do not block actions, wait scripts, heal, drink or retry anything. They do not change the shard's real cooldown rules. Repeated item-use requests while an estimate is running leave the existing deadline intact.

Settings belong to the current launcher profile. Keep separate profiles for separate shards, each with its own durations and message rules. Profile backups include saved definitions; running countdowns are temporary. Switching character/session clears temporary state, and old journal or action history is not replayed as new triggers.

Graphics

Start with Automatic. If your graphics driver needs a different renderer, choose a supported graphics option in the profile and start the game again. A steady Draw FPS counter measures application presentation, rather than the physical screen refresh rate.

Updates and uninstalling

Install an update into the same application folder. Close this application's launcher, game and assistant first. The installer does not stop unrelated clients.

Uninstall from Windows Installed apps or the Start menu entry. Your profiles, assistant definitions and logs are kept separately from installed program files and are retained after uninstalling. Your shard's client folder is never removed.

About this preview

The GPU client is based on ClassicUO. Assistant features draw on the useful behavior of Razor, Razor Enhanced, ClassicAssist, Orion and Injection. Common legacy macro imports cover an explicit subset; they do not execute arbitrary historical Python, C#, BASIC programs or assistant DLLs. New agents and shard-specific dialogs still need manual gameplay checks.

This development installer is not digitally signed. No accounts, passwords, world saves, shard game files or private development logs are included.

  • Visual bounded macro programs with conditions/repeats and a dedicated JavaScript editor with parsing, highlighting, completion and trace navigation.
  • Searchable categorized UO marker library with UOAM, Ultima Mapper XML and CSV import/export; native marker display and local loaded-terrain straight-line preview.
  • Prioritized property rules with AND/OR groups and match explanations, passive alerts and bounded crafting plans with fresh exact-gump replies and observed outcomes.
  • Launcher setup templates, preflight, explicit connection test, optional verified release feeds and local recovery-package verification.

Read the complete scripting guide or printable PDF. Twelve separate examples are in SDK/examples. The 44-method public JavaScript API is documented, including limits, observation and target/dialog ownership.

The marker library integrates UO formats into the native map; it does not embed the separate Ultima Mapper executable or its external sharing service. Terrain preview does not start walking or compute an unloaded-world route. GPU measurements show unavailable where the operating system cannot supply them. New launcher preferences automatically check the UO Assistant feed at www.uoassets.com. Existing saved opt-outs and custom feeds remain intact. A local signed recovery catalog is included.
