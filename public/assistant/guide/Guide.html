Eight categories, with tabs for related tools

Choose a category on the left, then a tab across the top. A second row appears when a tab has related tools. Save and Run buttons stay above the scrolling page, and Stop all is always at the top of the window.

Home: Overview, activity and journal, timers.

Character: Health and pets, targets and saved objects, equipment, combat and cooldowns.

Items: Bags and search, loot, moving and restocking, vendors and use-once items.

Tasks: Your task library, Simple steps, JavaScript, recorded actions, workflows, crafting, monitors and debugging.

Map & travel: Map and markers, walking and waypoints, runebooks, team map and recovery.

Controls: Hotkeys, keyboard and mouse bindings, action bars, display and sound.

Recording: Video capture, replay and recording settings. Action recording for macros is under Tasks.

Settings: Profiles, play styles, appearance, backups and diagnostics.

Find a tool accepts familiar words such as bandage, trees, bags and hotkey. Favorites retain your saved tools. Show advanced tools reveals specialist editors, inspectors and diagnostics. Opening an advanced tool from a direct link reveals it automatically. All previous features remain available.

Getting started with UO Assistant

A GPU game client with an assistant in its own window. Version 0.6.0 is an unsigned development preview.

Install

Run the setup EXE and follow the installation steps. Installation is for your Windows account. The client, assistant and their .NET runtimes are included; PowerShell and a development SDK are not required. Normal startup opens no command window.

Your shard's game data is separate. Use a complete client installation supplied for that shard, including its custom maps and artwork. Installing UO Assistant does not replace that folder or install game accounts or world saves.

Connect to a shard

  1. Open UO Assistant from the Start menu or desktop shortcut.
  2. Add a profile and choose the shard's client folder or client.exe. The launcher reads the version and available game data without running that executable.
  3. Check the address and port. Use the shard's own instructions for encryption. The launcher can read one active address from Login.cfg; enter a different address explicitly when needed.
  4. Review preflight results, save the profile and choose Play. The GPU game client and separate assistant open together. Log in manually in the game.

Use separate profiles for different shards, client versions, custom maps and timing rules. Each profile keeps its own character settings, history and assistant definitions.

First gameplay check

Start with Automatic graphics, a 60 FPS target and VSync. Walk/run, use and drag the backpack and paperdoll, double-click an object, dismount and try entity plus ground targeting. The compact CPU/Draw FPS display remains in the game. Draw FPS counts completed application frames; it is not a measurement of physical monitor refresh.

The assistant's navigation search and favourites help find tools. Ctrl+Shift+A opens its separate window. Configure a rule, inspect its preview and choose Run when ready. Saved watches and priority observers require an explicit start/arm; loading a profile does not start them.

Closing either the assistant or game closes its paired application normally. Stop all cancels further queued automation. Requests already sent to the shard cannot be recalled. Capture finalizes complete video when closing; leave time for a long clip to finish saving.

Set up shortcuts and an optional action bar

Open Input & action bars. Choose an action and a gesture, including modifiers, mouse side buttons or wheel. Select its Game/Targeting/Chat context, Tap/Release/Hold trigger and pass-through behaviour. Hold fires once after 350 milliseconds. Review conflicts before saving; ordinary left/right mouse use and reserved inputs stay available to the game.

Enable the optional native action bar and configure spells, skills, scripts, macros, targets, equipment, travel or recording controls. A displayed hotkey label does not create a binding by itself. Add an exact saved cooldown name to show its current labelled outcome. See game controls and the workflow guide.

Potion, bandage and custom countdowns

Open Cooldowns and choose Add example presets for editable potion and bandage rows. Existing profiles keep their definitions. Select a row, set Duration (seconds) to your shard's timing and save. Fractional seconds are supported; add named timers for abilities, buffs or other reminders.

Choose Manual, owned Item use, or a literal Journal message as the trigger. Starter automatic tracking is off until enabled. Match graphic and optional hue, or choose a loaded inventory item to supply them. An optional fresh ready message confirms readiness; configured failure/interruption text produces a different outcome. System-only observation excludes player speech. Timing & healing also supports explicit fixed or dexterity bandage formulas.

Use estimates as reminders: they do not prove the server accepted a use, alter real cooldowns, drink, heal, wait scripts or retry. Repeated use requests do not keep extending an active estimate. Definitions are saved per profile; active countdowns are temporary and reset with session changes. Old journal/history is not replayed as new triggers.

Inspect, organise and record a short task

Use the loaded inventory or Object inspector to identify an item, inspect known properties and create a portable alias, counter, protection, loot rule or use-by-type script. Open relevant containers first. Missing/unloaded facts do not establish a match.

Preview organizer/restock, named loot or batch move plans before running. Equipment selectors can match an exact item or loaded type/properties; choose an accessible undress bag when replacing equipment. Protected items and changed assumptions refuse a plan rather than redirecting it silently.

Start Gameplay recorder in the world, perform a short supported sequence, stop and save. Review steps and replace temporary item IDs before playback. Target/dialog replies wait for fresh state. Do not assume an observed request was a successful server result. Read the detailed workflow instructions.

Maps, recovery and runebooks

Expedition & recovery records a fresh death with facet/time. Save healers, numbered waypoints and a return point explicitly. Show a short current trail or plan a nearby loaded-terrain route; a preview starts no walking and a waypoint list does not walk itself.

Use Shard layers & coordinates to bind reviewed versioned marker/zone layers to a shard label and sampled map fingerprint. Preview duplicate/category changes before applying. Save a custom sextant origin before using sextant destinations. Existing Map library imports compatible CSV, UOAM and Ultima Mapper marker data. See the mapping guide for bounds and undo.

Runebooks & travel learns actual accessible book dialogs and local page choices. Save resource checks and the shard's literal failure messages. Each reply requires a fresh matching page; failure stops without retry. Save a destination coordinate when you need arrival confirmation rather than dispatch-only completion.

Optional team sharing and role layouts

The team page first shows shard-supplied party facts. External sharing is off at every startup. Connect explicitly to a trusted authenticated relay to share a chosen label/location and optionally known health/death, or send short-lived pings. The secret stays in memory. Sharing starts no movement or targeting. The optional included relay server is a separately started administrative tool; normal application startup does not open its console or deploy a service. Hosting and privacy instructions.

Capture a named role layout, review it, then apply while stationary with no active run. It pairs assistant workspace and game presentation/window placement, including uniquely matching already-open movable gumps. It does not open containers or start gameplay tasks. Undo restores the preceding layout while the assistant remains open.

Record a high-quality clip

  1. Enter the world and keep the paired game restored. Open Recording in the separate assistant.
  2. Start with Auto codec, Balanced quality, 60 FPS and the default 1920-pixel maximum width. Choose optional game-only audio/cursor and save settings.
  3. Choose Start recording, play normally, then Stop and save. Verify the MP4 before deleting any recovery files.
  4. Alternatively start the bounded replay buffer and choose Save replay to preserve recent complete segments. Set your own input/action-bar shortcuts.

Auto probes HEVC, AV1 then H.264 hardware encoders, with no silent CPU fallback. Game capture needs Windows 10 version 2004 or later; game-only audio needs Windows 11 or a supported server version. The microphone stays off. File size depends on scene, quality, resolution and frame rate. NVIDIA capture was tested; Intel/AMD capability is checked at runtime. Learn scripting

Use JavaScript and the installed API declarations. Start with a supplied information-only example, then use copied-fact offline simulation, source debugging and a short manual in-game run. Legacy translation reports blockers; it is not full historical-language compatibility. Visual workflows compile finite blocks/functions into the same checked executor. Priority observers remain disarmed until you arm them for the current session.

Read the full scripting guide, 63-page printable PDF, workflow additions and installed API declarations. Optional assisted editing only builds local context for your review; sending it to a provider and saving/running returned code are separate choices.

Graphics, diagnostics and sound

Keep Automatic graphics initially. If a driver needs another supported renderer, change the profile and restart the game. Compare normal play with recording off/on using Draw FPS, frame P95/P99, long frames and recorder drops. Reduce capture size or use 30 FPS if necessary. Missing OS GPU/VRAM counters are shown as unavailable.

Normal warning/error logs use a bounded background queue and limited private files; enable trace only when diagnosing an issue. Review logs before sharing, because they may contain local paths and server text. Nothing uploads logs or clips automatically. Sound presets let you listen to an observed sound ID and mute only that ID; focused journal filtering/highlights do not remove the original journal.

Updates and uninstalling

Fresh launcher preferences check the UO Assistant website feed at www.uoassets.com at startup and periodically in the background. Existing opt-outs and custom feeds remain intact. Updates & recovery provides manual checks, verified downloads and local recovery packages. Download/install require your choice; see Automatic updates.

Install an update into the same application folder. Close this application's launcher, game and assistant first. The installer does not stop unrelated clients. Uninstall from Windows Installed apps or the Start menu. Profiles, definitions and logs are stored separately and retained; the shard's client-data folder is not removed.

About this preview

The GPU client is based on ClassicUO, with new assistant tools inspired by Razor, Razor Enhanced, ClassicAssist, Orion, Injection and mapping research. Automated tests and controlled GPU fixtures exercise implementation and frame timing. They do not replace a manual movement, gump, targeting, travel and recording test on your particular shard and hardware.

The development installer is not digitally signed for Windows publisher identity. Signed update catalogs serve a separate integrity purpose. No accounts, passwords, world saves, game assets or private development logs are included. Read all feature areas, release notes and third-party notices.
