Game controls and playability

UO Assistant 0.7.0 preview keeps the game on its GPU renderer and the assistant in a separate window. Opening the application normally does not open a command window. Closing the separate assistant still closes its paired game.

Keyboard and mouse shortcuts

Use the playability editor to bind a normal game action, saved target preset, script, task, equipment set, travel destination or recording control. Shortcuts support letters, digits, F1–F24, Space, Tab, Backspace, Home, End, Insert, Delete, Page Up, Page Down, the middle mouse button, Mouse4, Mouse5 and the mouse wheel. Combine them with Ctrl, Shift and Alt. Left and right mouse buttons remain available for ordinary game controls.

Existing native client macros retain their shortcuts: conflicting new bindings are refused. Ctrl+Shift+A opens the separate assistant. Reserved system shortcuts cannot be captured. Use the master shortcut switch to turn assistant bindings off.

Saved target presets

A preset selects from mobiles already loaded by your client. Choose friendly, hostile or any; a maximum range; nearest, next, previous or lowest known health; a specific body; poison; known-health requirements; and exclusions for friends and renamable mobiles. Friendly and enemy selection history are separate. Cycling uses a stable serial order, so a nearby mobile changing distance does not repeatedly scramble the cycle.

Lowest health compares health percentages and ignores unknown health. Friendly matching uses your saved friends, party and known ally status. Renamable mobiles are excluded by default; this is an exclusion rule, not proof of pet ownership. Unknown notoriety and invulnerable mobiles are not classified as hostile. A harmful cursor cannot target a protected friend. Server line of sight and undisclosed ownership are unknown. The shard decides whether a requested action succeeds.

Use Select to highlight a matching mobile, Target to answer the current ordinary target cursor, or Attack to request an attack. A replaced or expired cursor is refused instead of applying an old target to a new action.

Casting and targeting conveniences

Use Casting & convenience to save optional observed hand clearing before manual spells or ordinary potions, recovery of the original weapon and shield, existing doors/corpses/display choices and war-mode dismount prevention. Remember current hands and Restore remembered hands are separate explicit actions. Stop all and Escape cancel pending hand work. Targeting & aliases offers separate harmful/beneficial last targets, optional last-target range checking and a fresh Heal/Greater Heal poison safeguard. Opening these tools keeps your existing game choices; Save & apply remembers your selections for this shard profile. Read the hand preparation, recovery and targeting guide.

GPU action bar

Enable the optional native action bar in the separate assistant and configure its slots there. Drag the bar by its border. It adjusts its columns to fit the game window. Slots can invoke spells, skills, ordinary controls, target presets, scripts, tasks, equipment, travel and recording controls. Each slot shows its shortcut and state. A tilde before a countdown means an estimate. Running, interrupted, failed, unknown and confirmed-ready states must be read as their labels describe; a local timer is not a server acknowledgement.

Cooldown and task-state updates do not reinstall key bindings or cancel a held shortcut. A displayed countdown is informational and does not make the client cast, move or use an item automatically.

Recording ordinary game actions into tasks

The task recorder can observe ordinary backpack or object use, casting, skills, item lifts and completed drops, equips, attacks, entity or ground targets, supported server gump, menu and text-entry replies, and local page changes. It records requests made while in the world, not account login. A requested move or spell is not a successful result from the shard.

Inspect a recording before replaying it. Replace temporary item serials with an alias or a matching item rule where appropriate. Dialog replies retain the observed identity for inspection; replay should wait for a fresh matching dialog and obtain its current identity. This prevents a later unrelated window from receiving an old reply. Keep the separate assistant's stop control available.

Sound, containers and game command panels

The sound tools list the 32 most recent observed sound IDs. Preview a sound using your normal game sound-volume and background-audio settings, then mute or unmute that ID. A preview bypasses only that ID's mute rule. Music, sound volume and footsteps remain separate native settings.

Choose traditional bags, native grid loot, or both. Changing this option does not move an item. Open the Pet, Boat or Custom panel from the companion's Controls / Commands page. These are separate draggable game windows; each named button speaks once on an explicit click or hotkey. Edit command text for your shard, including custom commands such as .sacall. Saving or opening a panel sends no speech. Kill leaves the target to you. Named patients, healing methods and command-panel guide.

Map routes and layouts

Runebook recipes can navigate a local page through its currently visible page button before using a destination. Each page change obtains the fresh dialog identity and changes only that local page; it does not send a server reply. A hidden page or replaced dialog is refused.

Terrain route previews use bounded A* search over already-loaded terrain, avoiding known static obstacles, steep elevation changes and blocked diagonal corners. A preview is limited to 65 route points and a small processing budget. Unknown tiles and a budget overrun can produce no route. The preview never starts walking and does not prove server walkability or account for future mobile obstacles.

Role layouts resize the game window and reposition matching windows that are already open. Apply a layout while stationary. They do not open bags, start scripts, change an account or load a saved world. Named zones from enabled map layers are drawn in the native world map.

Diagnostics and smooth gameplay

Normal logs contain warnings and errors. Trace recording is optional. The logger uses a bounded background queue and a private per-session file with a strict 8 MiB limit; it drops excess messages instead of waiting on disk from a game frame. Diagnostics report dropped messages so an incomplete log is visible.

Draw FPS counts completed renderer presents. CPU is normalized across the machine's processors. P95 and P99 show frame-interval percentiles over the retained 240-frame window; long frames exceed approximately 33.3 milliseconds. These are client-side measurements, not physical monitor FPS, GPU utilization or network latency.

Broad world and inventory snapshots remain sampled four times per second. A small coalesced urgent channel sends new targets, dialog changes and action observations sooner without copying the inventory again. Updating an urgent cursor does not make old inventory data appear newly captured. Every command still checks the current session, cursor, item facts and shard feature policy.

Final movement, targeting and shard-specific dialogs should be checked in a player session. Automated native UI and recording tests use network-fenced synthetic scenes; their performance does not establish every live shard's frame rate.
