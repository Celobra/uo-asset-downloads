UO Assistant 0.7.1

18 October 2026 · unsigned Windows x64 development preview

Choose game objects and positions directly, with quick loot, scavenger and vendor rule setup.

What changed

  • Use the paired game cursor to choose objects and positions in the assistant instead of copying numeric IDs.
  • Loot and scavenger rule libraries offer Target item to add. A valid selection saves a named type-and-colour rule; repeated matching selections do not create duplicate rules.
  • Target loot bag saves a loaded accessible container as the selected set destination. Target item to protect saves an exact-item protection. Picking and saving do not move items or start a watch.
  • Vendor buy/sell rules offer Target item to add with the visible quantity, price and keep limits. Target vendor uses an already open matching vendor quote; picking does not trade.
  • Object, type, colour and location fields provide game selection across assistant tools. Field pickers name the next Add/Save action; direct counter, equipment and use-once buttons save their stated definition.
  • Location picking checks the current facet; map and travel presets also save the selected facet with their coordinates. Unavailable, cancelled, stale or invalid selections leave saved definitions intact.
  • Setup identifies and removes earlier installed UO Assistant versions before copying the update, preserving profiles, scripts and user-added files. Isolated upgrade checks passed against the retained 0.6.0 legacy setup and the actual published 0.7.0 installer sources.
  • The separate assistant, GPU renderer, existing scripts, advanced JavaScript tools, command panels and user profiles remain available.

Using game selection

Open Items / Loot / Loot & scavenging, choose the Loot or Scavenge library and set, then choose Target item to add or Target loot bag. Click the intended object in the game. These quick actions save the rule or destination without running the task. For field pickers, selection fills the visible fields; review them and use Save.

Limits and compatibility

  • Unsigned Windows x64 development preview.
  • Targeting requires a connected paired game and currently observed game facts. Open containers or the relevant vendor quote before choosing their contents or vendor.
  • Synthetic interface and protocol checks do not prove live shard targeting, permission responses or populated-world gameplay. These still require manual testing.
  • Existing PDF reference manuals retain their accurate 0.7.0 edition. The new HTML targeting guide documents this release.
