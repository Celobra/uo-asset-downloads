UO Assistant 0.3.0

16 October 2026 · Windows x64 · Unsigned development preview

Getting started · Features · Release notes · Scripting guide · 63-page PDF · Workflow guide · Maps, travel and teams · Game controls · Recording · Updates · Recording source

A quieter GPU client with a separate assistant, richer input and scripting tools, native map and travel features, and hardware video recording.

The game and assistant open together. Normal startup no longer opens a command window. Closing either window closes its paired application normally; closing the assistant also finalizes an active capture. Saved scripts, watches, observers, recording and team sharing require an explicit start.

Game controls and smooth rendering

  • Keyboard, mouse side-button and wheel bindings with modifiers, Game/Targeting/Chat contexts, Tap/Release/Hold and individual pass-through. Holds fire once after 350 milliseconds; key repeat does not repeatedly launch actions.
  • An optional draggable native GPU action bar for spells, skills, targets, scripts, macros, equipment, travel and recording. Counts and task/cooldown state distinguish estimates from confirmed observations.
  • Saved target presets with stable cycling, nearest/previous/next/lowest-known-health choices, filters and separate friendly/enemy history. Current target ownership and friend exclusions still apply.
  • A small urgent event channel delivers fresh target, dialog and action changes sooner. Broad world/inventory snapshots stay sampled, keeping avoidable copying outside the render loop.
  • Bounded background warning/error logging, optional trace, CPU/Draw FPS, frame P95/P99, long frames and diagnostic counters. Unknown OS GPU/VRAM measurements remain labelled unavailable.

High-quality hardware video and replay

Capture the paired game window with selectable HEVC, AV1 or H.264 hardware encoding, Compact/Balanced/Detailed presets, 30/60 FPS, output-width and bitrate choices. Auto probes HEVC first, then AV1 and H.264. Controlled small-text tests favoured HEVC for size at comparable measured detail; this is not a universal codec ranking.

Optional game-only audio leaves the microphone off. A bounded encoded replay buffer saves recent complete segments while capture continues. Trimming creates a compressed copy near keyframes, preserving the original. Complete recovery chunks remain available after an export failure. Clips stay local. See Recording and licenses, corresponding source and rebuild instructions.

Editable tasks and better inventory tools

  • Record ordinary supported game actions, including item use/moves/equips, casts, skills, targets and dialog replies. Review the recording, replace temporary object IDs with aliases/type matches, or play a valid selected slice. Playback obtains fresh target and dialog authority.
  • Inspect a loaded object and create an alias, counter, protection, named loot rule or portable use-by-type script. Search and compare loaded inventory, preview finite batch moves and choose traditional bags, grid loot or both.
  • Named priority loot rules with readable AND/OR property groups, explanations and per-rule destination bags. Equipment sets can use loaded type/property selectors, ranking and an explicit undress bag.
  • Patient lists, server-identified controlled pets, editable fixed/dexterity bandage timing and explicit ready/failed/interrupted journal outcomes. Local countdowns remain estimates unless a configured fresh message confirms an outcome.

Scripts, migration and coordinated automation

JavaScript remains the primary language. The source debugger can pause at real source statements and inspect primitive locals and call stacks. An offline bench evaluates against copied facts and logs simulated operations without a game connection. Visual workflows add finite blocks and reusable nonrecursive functions; local script manifests and templates track reviewed versions.

The UOSteam/Razor migration page translates an explicit supported subset and blocks incomplete conversions. In the read-only supplied corpus audit, 32 of 200 UOSteam scripts converted completely; none was executed. This is syntax coverage, not proof of shard compatibility or complete historical-language support.

Priority observers share the existing single action runner. Arming is explicit for the current character session; movement, manual actions, held items and active targets take precedence. Optional assisted editing builds a local reviewable context from selected source and documented API signatures. It neither contacts a provider nor executes generated code automatically.

Maps, expeditions, travel and role layouts

  • Fresh death records with facet/time, explicitly saved healers, numbered waypoint routes, a return point and a bounded temporary trail.
  • Versioned per-shard map layers bound to a sampled map fingerprint. Preview imports, category remapping and duplicates; draw polygon zones, undo recent layer edits and enter sextant coordinates using an explicitly configured custom origin. Existing compatible CSV/UOAM/Ultima Mapper marker imports remain available.
  • Bounded obstacle/elevation-aware A* previews over loaded terrain. Unknown tiles are not assumed walkable; a preview does not start movement or establish a route across an unloaded world.
  • Runebook presets learned from actual loaded dialogs, including local page transitions and fresh subsequent replies. Resource checks, literal failure messages and optional arrival confirmation stop uncertain travel without automatic retries.
  • Shard party data first, with optional authenticated self-hosted team sharing, stale-state labels and short-lived help/rendezvous/marker pings. Sharing is off each time the assistant starts; no external relay is deployed automatically.
  • Named game/assistant role layouts with preview and last-apply undo. They reposition already-open matching gumps and presentation settings without opening containers or starting tasks.

Sound, readability and existing tools

Preview and mute observed sound IDs; read a focused journal with literal highlights, source filters and repeat folding. Existing workspace text size, contrast, favourites, docking and placement recovery remain available. Organizer/restock, counters, protection, vendor plans, healing, crafting, aliases, backups and checked script APIs remain part of the application.

Setup, updates and documentation

Use separate launcher profiles for different shard client-data folders, versions and connection settings. Fresh preferences check www.uoassets.com for updates in the background. Existing opt-outs and custom feeds are preserved. Downloading and installation remain explicit choices with application identity, signature, exact-size and hash checks. Read Automatic updates.

The updated scripting guide and 63-page PDF cover the installed API and examples. The workflow guide, maps/travel/team guide and native controls guide describe the actual editors and limits.

Validation and remaining gameplay checks

Tests exercise native input/leases, protocol state, checked automation, migration/debugging, map/travel/team fixtures, WPF save/preview handlers, dependency/source verification and hardware recording. A controlled network-fenced GPU UI benchmark ran near 60 FPS before and during recording. NVIDIA hardware capture was exercised; Intel and AMD paths are runtime-probed and need receiving-system tests.

These are automated and synthetic rendering/capture results. This release does not claim a new live-world walking, crowded-shard, custom-gump or every-GPU acceptance test. Test movement, gumps, object clicks, targeting, the shard's travel messages and a short clip on your own system. No accounts, passwords, world saves, shard game data or private logs are distributed. The Windows installer is unsigned; release-catalog integrity signatures are a separate mechanism.
