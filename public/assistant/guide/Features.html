Getting started · Release notes

Your game, with a separate assistant

The companion opens with the GPU client. Keep the game window for movement, targeting and gumps; use the companion for information, shortcuts and tools.

Log in manually as usual. Nothing starts playing, healing, moving items or running a script at login. The game retains its compact CPU, Draw FPS and frame-time display. Using the companion keeps the game at its normal frame-rate target.

First test

  1. Walk and run in the game. Check that it remains smooth when you switch to the companion.
  2. Use the companion’s backpack, map, journal and paperdoll shortcuts, then use and drag their normal game windows.
  3. Open a game target cursor and try Self, Last Target, a selected mobile or a ground location. Test dismounting while mounted.
  4. Inspect the journal and inventory. Start with the supplied information-only script before making your own action sequence.
  5. Try Stop All during a macro or wait. Closing the assistant also closes its paired game normally; closing the game closes the assistant. Both save their own settings.

Tools in this build

Dashboard

Player health, mana, stamina, weight, position and connection state, alongside CPU, Draw FPS and frame P95. Draw FPS counts completed application frames.

Journal

Search the bounded live journal by text. Macros and scripts can wait for fresh matching messages, with a timeout and cancellation.

Inventory and counters

Search loaded items, inspect their graphic, hue, amount and container, and create named stack counters. Unopened or incomplete inventory is identified.

Targeting and aliases

Self, last, entity and ground targets, plus named object selections and friends. Target actions use the exact current cursor; a replacement cursor stops the action.

Hotkeys

Bind supported actions, macros and scripts. Typing in the game takes priority. Repeated key events do not repeatedly launch an action.

Macros and scripts

Edit ordinary action steps, pauses and waits, or write JavaScript. Record manual supported actions without recording the recorder’s own playback. Each run is bounded and cancellable.

Organizer and restock

Match graphic and optional hue. Preview the moves before running. Restock calculates the missing quantity; queues wait for an observed inventory change and stop on failure.

Equipment

Capture and name your current equipment, then request that set later. Each equip is checked against the current item and layer and waits for the change.

Timers and preferences

Named local countdowns and per-profile settings. The companion does not save a login name or password.

Loot and scavenging

Choose graphic, hue, name and cached property rules, a destination and a range. Preview loaded matches, run once, or explicitly start a bounded watch. Protect important items from automatic moves and sales.

Vendors

Inspect the current vendor offers, calculate an order and set quantity and price limits. A changed price, stock or open vendor window invalidates an old order. Native vendor selection remains available in the game.

Healing and use-once

Configure health, mana, poison and cooldown conditions for a bandage or healing spell. Run once or start a bounded watch. Use-once processes a selected item list; a trap pouch must be explicitly identified.

Dialogs and prompts

Inspect currently open server gumps, menus, text entries and prompts. Replies are checked against that exact window and its current options. Replaced windows require a fresh selection or wait.

Travel and combat

Request native pathfinding to a nearby loaded location, stop walking, place a temporary Go-to marker, change war mode or use supported combat abilities. Saved friends and known native party members are excluded from assistant attacks and harmful targets.

Display and sound

Adjust supported light, weather, vegetation, sound and music options. CPU, completed Draw FPS and frame P95 remain visible in the game. The assistant respects shard feature restrictions.

Script files and trace

Import or export JavaScript, translate supported Razor/UOSteam macro commands, and inspect unsupported-command errors before running. Pause, step and breakpoints operate at supported action/API boundaries.

Profile backup

Back up and restore assistant definitions with format and checksum validation. Existing definitions are checked before replacement. A backup includes your scripts, object selections and rules; choose its destination yourself.

Writing a script

The default scripting language is JavaScript through Jint. The editor supports top-level await. Read a copied snapshot with await assistant.snapshot(), print with await assistant.log("text"), and use the supplied examples to learn actions and waits.

A script has no filesystem, process, network or CLR access. Its game actions go through the same checked controls as the buttons. Stop All prevents further queued requests; an action already sent to the shard cannot be withdrawn.

Macros, aliases, counters, equipment and agent rules are saved for the selected profile. Common Razor .macro and UOSteam text commands have an explicit importer. Unsupported commands are reported and prevent an incomplete translation from running. Python, C#, BASIC and arbitrary Orion programs need adapting to this JavaScript API.

External editors can use the supplied assistant.d.ts declarations. They provide command and snapshot completion; scripts still run only in the companion. The trace steps across API calls and macro actions, rather than arbitrary JavaScript statements.

Using agents without interrupting play

Open the relevant containers or vendor in the game first. Add rules, review the preview, then choose Run once. Watches start only when you choose them and stop at their configured time limit, Stop All, disconnect or a character change. A manual target or held item takes priority. Automated actions stop when their assumptions change instead of repeatedly retrying.

Only one companion run owns automation at a time. Stop the current run before starting another. You can keep playing normally while information, rule planning and script execution run in the separate assistant process. Native menus, map tools, spell buttons and ordinary game controls remain available.

Properties come from the client’s existing cache. Missing properties or incomplete loaded state do not establish a match. The assistant does not scan the entire shard, force remote property requests or increase the server’s movement speed.

Scope and validation

The companion is tested with isolated game state and local connections. Shard-specific tools and new agents still need manual gameplay checks.

The new features use supported native game actions. Imported macros cover an enumerated common subset; this is not full compatibility with every historical assistant language or plugin. Pathfinding is limited to nearby loaded terrain. Shard-specific trading, crafting and gump layouts need suitable user rules and manual verification. New agent code was written for this client rather than loading the archives’ assistant DLLs.

Potion, bandage and custom countdowns

Open Cooldowns in the separate assistant. Choose Add example presets for editable healing potion, cure potion and bandage rows. Existing profiles keep their current definitions. Select a row, set Duration (seconds) to your shard's timing, then save it. Fractional seconds are supported. Add other named timers for abilities, food, buffs or any reminder you need.

Choose Manual to start/reset a countdown yourself, Item use to observe an owned item's use request, or Journal message to start from a literal message your shard sends. Automatic tracking is off for the starter rows until you enable it. Match an item's graphic and optionally its hue (a blank graphic matches any owned item use); a loaded-inventory selection can supply those values. Journal matching uses literal text, not a programming expression. An optional ready message ends the countdown early.

A potion-use countdown estimates when the action may be ready; a request can still be refused by the shard. A bandage countdown estimates the completion time after the configured start message. These timers do not block actions, wait scripts, heal, drink or retry anything. They do not change the shard's real cooldown rules. Repeated item-use requests while an estimate is running leave the existing deadline intact.

Settings belong to the current launcher profile. Keep separate profiles for separate shards, each with its own durations and message rules. Profile backups include saved definitions; running countdowns are temporary. Switching character/session clears temporary state, and old journal or action history is not replayed as new triggers.
